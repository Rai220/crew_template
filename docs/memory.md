# Протокол памяти

Память, опыт и история работы хранятся локально в файлах персонажа. Обновляй их по ходу работы; контекст диалога не является постоянным хранилищем. Git используется для согласованной синхронизации и версионирования, локальная работа возможна без него

Сначала карта, затем тематический индекс и нужная карточка. Историю читай для конкретного вопроса. Поиск по умолчанию охватывает активную память; архив подключается явно

## Запись

Сначала ищи дубликат. Сохраняй решения с причинами, ограничения, неудачные подходы и прямые просьбы пользователя. Если нового знания нет, запись не нужна

Одна карточка - одна тема. Обязательные поля фронтматтера: `name`, `description`, `type`, `updated`. Имя совпадает с именем файла без расширения. Тип: `feedback`, `lesson`, `bitter_lesson`, `project`, `reference`. Дата `YYYY-MM-DD`. Формат - простые однострочные значения, образцы в [examples](../examples/README.md)

В теле указывай источник, область применения и дату фактической проверки. `updated` отражает редактирование. Различай проверенный факт, сообщение пользователя и гипотезу. Для инфраструктуры указывай машину и проверенный путь; для внутренних ссылок используй относительный Markdown

- Прямую поправку пользователя храни в feedback, со ссылкой на источник решения
- Свой вывод из ошибки храни в lessons, с доказательством и условиями применимости
- Дорогую ошибку или долгий неудачный подход разбери в bitter_lessons: попытки, результат, цена, причина, действие на следующий раз и ссылка на задачу. Не дублируй тот же урок в lessons
- В projects остаются действующие договоренности и открытые вопросы
- Ход работы и временные статусы храни в journal; устаревшее - в archive со ссылкой из действующей карточки
- Каждую содержательную задачу или эксперимент заноси в [journal/TASKS.md](../journal/TASKS.md). Перед завершением сессии обновляй результат, проверку и статус. Это учет работ, он ведется и тогда, когда нового устойчивого знания нет

Новую карточку добавляй в README ее раздела. В индексах только краткое назначение и ссылка, без копии содержимого

## Актуальность и совместная работа

Перед применением сведений о версии, сервере или пути проверь источник. Старое "работает" не подтверждает сегодняшний доступ. Давность задачи не означает завершение

При изменении решения перепиши действующее утверждение; исходное свидетельство при необходимости сохрани в архиве. Не выбирай версию только по дате файла. Не выкидывай полезные данные ради размера

Перед записью перечитай файл: другое окно могло его изменить. При синхронизации через git разбери конфликт по смыслу. Worktree не решает конфликт общих знаний автоматически

После изменения: `python3 scripts/check_memory.py`. Разбери предупреждения размеров. Секретов и чужих персональных данных здесь быть не должно
